# gold_annot - manually curated annotation store

Hand-curated annotations that are too expensive to regenerate and too
manual to derive from the gold build. This is the operative store for the
GT-cycle calibration marks ("user marks a period where the machine ran").
It is intentionally tracked in git (un-ignored in .gitignore): unlike
data/raw/, nothing here is re-downloadable - it exists only because a
human reviewed data by eye.

## Layout

- `<dataset>/<house>/cycles.csv` - cycle-level manual marks.

## cycles.csv schema

- `device` - gold appliance/channel name (must match appliance_map.json keys,
  e.g. `washing_machine`).
- `t_on_us`, `t_off_us` - cycle start/end as int64 UTC microseconds,
  consistent with the gold layer's timestamp convention.
- `source` - provenance tag of the curation pass, e.g.
  `manual_review_v1`. Increment the tag for each new review pass so the
  lineage of every mark is auditable.

## How marks are produced

From the visual review sheets generated by the GT-cycle EDA notebook
(src/pipelines/04_eda_annot_gt_cycle/, render in docs/reports/gt_cycle/):
candidates come from the gold rule on the submeter channel, the reviewer
keeps spans that cover exactly one coherent cycle (rejecting double-wash
spans, soak pauses, heavy simultaneous house load), and kept spans are
appended here with the current source tag.

Initial contents (2026-09 review): washing_machine house_1, 20 marks
seeds (source manual_review_v1), all inside the UK-DALE house_1
calibration span (before the notebook's 2013-10-01 split).

## Load contract

Notebooks load via baseline_lib.gold_annot_file(dataset, house, name) and
filter by device. The store is append-only by convention: never edit or
delete existing rows - extend with new source tags instead.
