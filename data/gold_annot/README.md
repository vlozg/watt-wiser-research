# gold_annot - manually curated annotation store

The GT-cycle annotation store: hand-curated marks that are too expensive
to regenerate, plus their rule-derived companions (burst-cycle lists,
device profiles, reserved test spans). This is the operative store for the
GT-cycle calibration marks ("user marks a period where the machine ran").
It is intentionally tracked in git (un-ignored in .gitignore): unlike
data/raw/, nothing here is re-downloadable - it exists only because a
human reviewed data by eye.

## Layout

- `<dataset>/<house>/manual_cycles.csv` - cycle-level manual marks (hand-curated
  program-device cycles; the only file edited by a human).
- `<dataset>/<house>/rule_cycles.csv` - rule-derived cycle marks for burst
  devices (kettle, microwave), regenerated by
  src/pipelines/04_eda_annot_gt_cycle/02_build_rule_profiles.py. Never
  hand-edited; a rerun overwrites it.
- `<dataset>/<house>/device_profile.csv` - one row per gold device (all
  channels, not just curated ones): `in_focus` flags the devices a
  curation pass targets; `class` (program / burst / duty / manual /
  heating / always_on / electronics / lighting / misc / excluded); the
  threshold actually used with its provenance (gold / override /
  generic-fallback); candidate rule parameters (per class: program
  600/600, manual 30/300, burst 30/60; non-focus rows fall back to a
  generic 20 W threshold, 30 s dwell, 60 s merge); and measured summary
  stats (n cycles, p50 duration/energy, power percentiles). The
  "what a product would say about this device" file, regenerated by
  src/pipelines/04_eda_annot_gt_cycle/02_build_rule_profiles.py.
- `<dataset>/<house>/splits.csv` - the reserved test span boundary (one
  row: `split_us`, UTC date, basis). Marks used for curation and profiles
  come from before the split; the span after it is held out for evaluation.

Two cycle files, two owners - the filename states the policy:

| file | written by | update policy |
|---|---|---|
| `manual_cycles.csv` | a human reviewer | append-only; scripts never write it |
| `rule_cycles.csv` | 02_build_rule_profiles.py | regenerable; truncated on every rebuild, never hand-edit |

Downstream code should not care which file a mark came from - load the
union via `baseline_lib.gt_cycles(dataset, house)` (adds a `provenance`
column, `manual` or `rule`).

## manual_cycles.csv schema

- `device` - gold appliance/channel name (must match appliance_map.json keys,
  e.g. `washing_machine`).
- `t_on_us`, `t_off_us` - cycle start/end as int64 UTC microseconds,
  consistent with the gold layer's timestamp convention.
- `source` - provenance tag of the curation pass, e.g.
  `manual_review_v1`. Increment the tag for each new review pass so the
  lineage of every mark is auditable.

## How marks are produced

From the visual review sheets generated by the GT-cycle EDA notebook
(src/pipelines/04_eda_annot_gt_cycle/, render in docs/reports/gt_cycle/):
candidates come from the gold rule on the submeter channel, the reviewer
keeps spans that cover exactly one coherent cycle (rejecting double-wash
spans, soak pauses, heavy simultaneous house load), and kept spans are
appended here with the current source tag.

Initial contents (2026-09 review), all `manual_review_v1`, all inside the
per-house calibration span (before the reserved split):

- house_1: washing_machine, 20 marks.
- house_2: washing_machine 20 + dishwasher 20 marks (sheet thresholds
  81 W / 90 W; the 90 W dishwasher override replaces the 984 W gold
  threshold, which only captured the heater plateau - see the
  house_2 overlay figure in docs/reports/gt_cycle/).
- house_5: washing_machine 20 + dishwasher 20 marks (sheet thresholds
  50 W / 48.5 W; the 50 W washer override replaces the 7.5 W gold
  threshold, which merged whole days into one span; house_5 mains idle
  ~550 W median, so the 01 activation hysteresis is per-house there).

Rule-derived burst cycles exist for kettle (all houses) and microwave
(houses 1-2; the house_4 mixed channel and the house_5 constant-draw
channel are classed `excluded` in device_profile.csv).

## Second curation pass (manual_review_v2, 2026-09)

A metadata-driven pass extended manual curation beyond the washers: every
episodic device with a recognizable on/off cycle shape got a candidate
sheet (per-class candidate rules on the submeter, generic 20 W fallback
for devices without a gold threshold), and 20 spans per device were kept
as exactly-one-coherent-cycle marks, clipped to the surrounding activity
edges. All marks are pre-split (inside the calibration span) and tagged
`manual_review_v2`. Devices curated (20 marks each):

- house_1: toaster, hoover, hair_dryer, straighteners.
- house_2: running_machine, rice_cooker, toaster.
- house_5: electric_hob, nespresso_pixie, oven, toaster, treadmill,
  hairdryer.

Per-device guards used during curation (recorded here because they encode
reviewed judgment): hoover max duration 9,000 s; straighteners min peak
80 W + max duration 5,400 s (standby-idle contamination of the channel);
rice_cooker min peak 400 W + max duration 10,800 s (cook plateau ~400 W,
warm-hold far below). Candidate sheets come from notebook 04
(docs/reports/gt_cycle/04_ukdale_all_device_eda.ipynb); each stored span
was numerically audited (duration/peak/on-power sanity) and visually
confirmed against mains + submeter before acceptance. house_3 and
house_4 have no curated devices (no episodic cycles pass the sheets).

## Load contract

Notebooks load via baseline_lib.gold_annot_file(dataset, house, name) and
filter by device, or baseline_lib.gt_cycles(dataset, house) for the union
of both cycle files. The manual store is append-only by convention: never
edit or delete existing rows - extend with new source tags instead. The
rule files are the opposite: regenerate, never hand-edit.
